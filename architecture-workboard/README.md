# Atlas — локальная карта архитектуры C#

Рабочая локальная версия: Roslyn/MSBuild анализирует исходники, React Flow отображает собственные карточки Atlas, зоны размещаются на едином полотне с отдельными коридорами связей, Monaco показывает исходный код. Старый макет сохранён в `prototype/`.

## Запуск

Требуется Node.js 20.19+ и .NET SDK 10. Для анализируемых проектов также нужны их SDK/targeting packs и восстановленные NuGet-зависимости.

```sh
npm install
npm start
```

Открыть http://127.0.0.1:4318. В меню выбрать «Открыть проект» и указать абсолютный путь к `.sln`, `.slnx` или `.csproj`. Кнопка «Открыть пример» анализирует настоящий проект `samples/Commerce/Commerce.csproj`. Пример не выполняется.

`ATLAS_DOTNET` задаёт путь к dotnet; запуск автоматически находит SDK в `~/.local/share/atlas-dotnet`. `ATLAS_PORT` меняет порт локального сервиса. Для разработки запустить сервис с `ATLAS_PORT=4320`, затем `npm run dev` (4319).

## Поведение

- Карточки классов крупные; ƒ раскрывает методы. Клик выделяет входящие/исходящие связи и открывает исходный код, фон снимает выделение, перетаскивание фона сохраняет выбор.
- Методы различаются семантическими идентификаторами, включая перегрузки. Частичные типы объединяются. Конструкторы, методы, явные аксессоры и локальные функции входят в карту.
- Единственный переход — выбор крупного компонента (например, NotificationService или NotificationAdmin). Дальше все его типы, включая вложенные, находятся на одном полотне. Пагинации и переходов внутрь папок нет.
- Зоны опираются на проекты, слои, модули и первую значимую папку, включая её потомков. Namespace — запасной источник. Полный путь и слой сохраняются в происхождении класса; одинаковые названия в разных слоях различаются подписями и цветом рамки.
- При отдалении (<30%) отображаются зоны и агрегированные связи между ними. При приближении появляются классы на тех же координатах. Нажатие названия зоны приближает её на общем полотне. Поиск и ◎ также двигают камеру, сохраняя окружение.
- Кнопка с пунктирной рамкой рядом с ƒ переключает обычные зоны и полупрозрачные цветные подложки без рамок, подписей и действий по нажатию. Карточки, связи и координаты сохраняются; в приглушённом режиме дальний масштаб тоже показывает классы. Настройка сохраняется локально.
- ◫ управляет видимостью зон. Скрытие убирает карточки и все связанные с ними линии без перестройки остальных позиций. Tests и Generated изначально скрыты; их можно включить. Внешние зоны содержат непосредственно связанные типы соседних компонентов, а не весь соседний компонент.
- Интерфейс показан ровно один раз, рядом с известными реализациями. Выбирается зона с наибольшим количеством реализаций, с приоритетом текущего компонента при равенстве. Наследование интерфейсов учитывается; циклы ограничены. Исходное расположение контракта остаётся в подписи и подсказке. Вызовы продолжают указывать на контракт, runtime-реализация не выдумывается.
- Размещение зон и общих маршрутов считается в Web Worker. Классы внутри зоны упорядочены с учётом зависимостей, контракты располагаются рядом с реализациями. Линии используют промежутки между карточками и обходят соседние зоны. Наведение, выбор, масштаб и скрытие зон не запускают раскладку.
- Список связей сохраняет исходные отношения и их виды. На дальнем масштабе внутренние связи зоны свёрнуты, на ближнем фоновые связи объединены по парам классов; выбор метода раскрывает точные порты и его вызовы. Ссылки проектов доступны на первом экране компонентов.
- Рабочие подборки приближают нужные классы на общем полотне. Камера, режим функций и видимость зон сохраняются локально. Функции меняют размеры карточек и перестраивают полотно; ручное размещение пока отключено.
- Изменения исходников/проектов проверяются каждые 1.5 секунды. После изменения solution повторно загружается через MSBuild и пересчитывается снимок, без выполнения целевого приложения. Это пока полное переиндексирование, не инкрементальный компилятор; на больших решениях оно занимает больше времени.
- Git сравнивает файлы с HEAD (staged + unstaged + untracked), статусы на классах/методах относятся к файлу. Удалённые файлы видны в состоянии анализа. Без Git анализ кода работает.
- «Сравнить коммит / PR…» строит отдельную карту изменённых типов из выбранного Git-снимка. Коммит по умолчанию сравнивается с родителем, PR `#123` — с общей базой текущей ветки; базу можно задать вручную. Исходники ревизии загружаются в отдельную временную рабочую копию без переключения текущей ветки. Для PR требуется доступ к `origin`.
- Ошибка нового открытия сохраняет предыдущую карту. Ошибки компиляции и неразрешённые вызовы видны в состоянии анализа. Частично разрешённый проект не маскируется под полный.
- Пунктир отмечает реализацию, наследование и ссылки проектов. Вызовы указывают на статически определённую цель, а не предполагаемую runtime-реализацию. Внешние библиотечные вызовы не визуализируются. Reflection, фактические DI-привязки, runtime delegate targets и неявные вызовы property accessor не выводятся как точные связи.
- Набор данных и настройки вида локальные. Настройки хранятся в `.atlas/`, исходники не изменяются. Панель кода только для чтения. Агенты и редактирование кода — следующий этап, не часть этой версии.
- При первом открытии Atlas создаёт у решения `.atlas/`: `architecture.md` с контекстом и форматом, `methods.json` с автоматически обновляемым индексом методов, `pipelines.json` для именованных последовательностей и `index.json`. После правки `pipelines.json` карта автоматически перечитывает метаданные и показывает сценарий в меню ⇢. Автоматические сценарии строятся по статическим вызовам; документированные сценарии дополняют их и не меняют исходный код.

## Локальный API

- `POST /api/open` — `{ "path": "/absolute/Project.sln" }`, возвращает снимок графа.
- `GET /api/graph` — текущий снимок, стабильные идентификаторы символов, реальные фрагменты кода, связи и диагностика.
- `GET /api/status` — версия снимка, состояние анализа и последняя ошибка.
- `GET/POST/DELETE /api/preview` — временный архитектурный черновик поверх текущего снимка. Предложенные типы и связи видны на карте с пометкой `PLAN`, затрагиваемые существующие типы — с `TOUCH`. Исходники не меняются; закрыть черновик можно в меню карты.
- `GET/POST /api/view` — позиции, текущая область, режим и пользовательские подборки для открытого проекта.

Для архитектуры до правок в Codex есть локальный скилл `$atlas-preview`: например, `$atlas-preview Покажи архитектуру очереди уведомлений до изменений`. Он изучает текущий граф и исходники, публикует предложение через `/api/preview` и оставляет реализацию на отдельный запрос. Для уже существующих изменений есть отдельный `$atlas-review`: например, `$atlas-review Проверь коммит abc123 в Atlas` или `$atlas-review Проверь текущие изменения в Atlas`. Он открывает реальный диф на карте и помогает проверить его влияние на зависимости.

Сервис слушает только loopback, проверяет Host/Origin и принимает POST только с JSON. Открывайте доверенные проекты: MSBuild читает project targets. Не выставляйте сервис в публичную сеть. Это локальное приложение; cloud Sites не используется для работы с исходниками.

## Проверки

`npm run build` — сборка интерфейса. `npm test` — тесты графа и маршрутизации. `ATLAS_TEST_URL=http://127.0.0.1:4320 npm run test:integration` — интеграционные проверки на отдельном запущенном сервере (откроют временный тестовый проект).

## Границы текущего алгоритма

Реализовано автоматическое структурное разбиение и единое полотно зон без ИИ. В модели есть данные о проектах, тестах, вложенности, доступности и generated-коде. Распознавание бизнес-контекстов только по графу зависимостей, анализ DI-фабрик/регистраций и внешних интеграций, runtime-сценарии и закрепление произвольных координат ещё не реализованы. Ошибки загрузки зависимостей исходного решения ограничивают полноту стрелок; структура папок остаётся доступной. Подробный целевой дизайн: `docs/architecture-graph-design.md`.

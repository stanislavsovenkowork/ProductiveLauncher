# Менеджер пользовательского LaunchAgent — кандидат

Менеджер не устанавливается автоматически. Это отдельный исполняемый файл `Contents/Library/HelperTools/FocusDeckUserAgentManager`, встроенный в пользовательскую сборку до её подписи скриптом `build-into-app.sh /absolute/path/FocusDeck.app`. Его команды: `status`, `install`, `update`, `uninstall`. Каждая возвращает JSON `{ "ok": true|false, "state": "absent|ready|active|unknown", "reason": "..." }`; ненулевой код выхода означает неподтверждённое действие. UI интегрирует владелец Mac.

Перед каждым изменением UI обязан убедиться, что `SMAppService.agent(...).status == .notRegistered`. Менеджер дополнительно отказывает при загруженной SM job, чужой/недоступной собственной job или занятом сокете; сам факт SM-регистрации вне UI он не проверяет. Собственная job имеет отдельное имя `dev.stanislav.focusdeck.userprotection.manual`. Менеджер проверяет владельца и содержимое своего plist, сохранённый хэш, подпись и CDHash агента; работающее состояние подтверждается на том же соединении сокета через UID, PID и CDHash. Доверие остаётся в пределах пользователя macOS, а не защищает от программ с тем же UID.

Для install и update существующая регистрация Chrome native host должна отсутствовать: сначала пользователь явно отзывает старый host, после успешной установки или обновления регистрирует host соответствующей новой сборки. Менеджер не перезаписывает даже чужой manifest. Он сверяет CDHash нового агента со встроенным в подписанный host через `--agent-hash`. При update новый app должен быть по отдельному пути; старый app и его подписанный агент должны оставаться доступными для отката. Перемещение/замена старой сборки до обновления может привести к `ownership_mismatch` и требует отдельного восстановления.

Обновление и удаление разрешены только при свежем ответе агента и завершённом окне (или отсутствии окна). Будущее расписание сохраняется; update и uninstall возвращают `schedule_boundary` при начале от текущего момента до 120 секунд включительно. Уже начавшийся интервал не считается будущей границей, но состояние окна всё равно проверяется: незавершённое окно блокирует действие. Ledger никогда не переписывается менеджером; его байты сверяются до и после остановки и обновления. При синхронной ошибке update он пытается остановить новый агент, вернуть прежний plist/record и проверить старого агента; `update_rolled_back` выдаётся только при подтверждённом возврате. Один маркер незавершённой операции заставляет последующий status вернуть `recovery_required` после прерывания. Он не является автоматическим восстановлением. При невозможности подтвердить cleanup или rollback состояние unknown; не удаляйте сокет автоматически. При uninstall ledger и будущее расписание остаются на диске, но работа службы прекращается до следующего явного включения.

Основные причины для UI: `installed`, `updated`, `uninstalled_ledger_retained`, `not_installed`, `connected`, `schedule_enabled`, `window_active`, `schedule_boundary`, `chrome_host_registered`, `chrome_pin_mismatch`, `service_conflict`, `new_bundle_required`, `ownership_mismatch`, `agent_unknown`, `launchctl_unknown`, `recovery_required`, `update_rolled_back`. `launchctl_unknown` означает, что команда состояния вернула ошибку или неожиданный ответ: это не считается отсутствием службы. Любой другой reason тоже следует показывать как неподтверждённое действие без предположения, что служба включена или выключена. Осознанный выход из активного окна выполняется прежним UI FocusDeck; независимое системное отключение доступно пользователю.

`python3 macos-study/user-agent-manager/tests/run.py` открывает собственный QA scope и проверяет только синтетическую job, агента и ledger в отдельном временном каталоге. Для дополнительных проверок использовался `tests/conflicts.py` с полученными synthetic артефактами. При неподтверждённой очистке scope остаётся открытым. На 2 ноября прошли установка, запрет update активного окна и регистрации Chrome host, обновление с побайтным сохранением ledger и будущего расписания, откат при отказе запуска нового агента, удаление с сохранением ledger; отдельно проверены чужой plist, занятый сокет, загруженная синтетическая SM job и несоответствие CDHash host. После каждого прогона собственных процессов, сокетов и job не осталось. [Evidence](tests/evidence-20261102.json).

Не проверены production-установка, пользовательский UI, полная внешняя SM-регистрация, перемещение app, аварийное прерывание update, аварийный stale socket, системный sleep/reboot/login и любые данные пользователя. Тест на отказ запуска проверяет только синхронный откат, не доказывает устойчивость к потере питания или убийству менеджера. Ранее наблюдавшийся SMAppService codesigning-отказ этим не диагностирован. Дальнейшее фактическое включение требует отдельной проверки и явного действия пользователя.

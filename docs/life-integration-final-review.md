## I1 · бывший P1 — закрыто по исходникам

Места: [LifeRepository.taskParents](../app/src/main/java/dev/stanislav/focusdeck/data/life/LifeRepository.kt#L173), [LifeViewModel.addActionToDay](../app/src/main/java/dev/stanislav/focusdeck/ui/life/LifeViewModel.kt#L253).

До исправления LifeVM мог получить родителей из снимка A, затем прочитать уже опубликованный rootKey B и записать задачу в B со ссылкой и ID из A.

Повторно проверены только два изменённых участка:

1. `taskParents` после refresh фиксирует `val index = snapshot.value`. Ошибка, папка, текущая запись и список предков читаются только из этого снимка; параллельная публикация B не смешивает их.
2. `addActionToDay` фиксирует `root` до `action {}`. Перед ожиданием проверяет непустой root, текущую папку и совместимость sourceRoot. После `taskParents` снова проверяет текущую папку, а в `editNoteOn` передаёт тот же захваченный `expectedRoot = root`.

Исходное чередование теперь приводит к отказу при смене A → B, а не к перенаправлению записи в B. Если папка не менялась, публикация другого снимка после разрешения родителей не меняет назначение операции.

**Сценарий для runtime-приёмки:** начать экспорт записи A, приостановить возврат `taskParents`, переключиться на B и опубликовать его индекс, затем продолжить экспорт. Ожидание: ошибка о смене папки; в B задача не появляется. Отдельно сменить папку между вызовом `addActionToDay` и запуском `action`: отказ должен произойти ещё до получения родителей. Эти чередования на устройстве в данном проходе не запускались.

## Остальная проверенная интеграция

- **H1:** taskParents перечитывает индекс, разрешает источник по ID и передаёт текущую запись helper. Предки и noteLink берутся из свежей записи, включая актуальный путь переименованного файла.
- **H2:** save нормализует proposal перед prepare, затем после merge сравнивает три родительских ID с canonical. Прежний сценарий независимых правок сферы/цели теперь отклоняется до записи.
- **Дата:** PlanningVM фиксирует targetDay перед coroutine/refresh и передаёт его в addTask/linkTask. LifeVM передаёт явную дату редактора в editNoteOn. Смена выбранного дня во время чтения родителей не перенаправляет эти операции.
- **Папка при записи daily:** captured expectedRoot проходит через VaultDayStore до VaultRepository; проверки стоят до/после чтения и перед записью. Исправление I1 фиксирует также выбор самого expectedRoot до ожиданий.
- **Сохранение life-записи:** проверяется sourceRoot, свежая версия файла проходит merge, корень сверяется перед фактической записью. Дополнительного конкретного дефекта merge в этом проходе не выявлено.

Это статическая проверка интеграции. Ранее зелёные тесты helper/кодека не являются проверкой описанного межпоточного чередования.

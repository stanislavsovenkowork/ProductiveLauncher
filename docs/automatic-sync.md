# Автоматический обмен метриками через существующий Syncthing

Это локальная публикация событий в уже выбранную синхронизируемую папку. Нового облака, LAN HTTP, bearer-сервера или пересылки сообщений нет. USB/ADB reverse относится только к лабораторной проверке и не является обычным каналом работы.

## Подтверждённая конфигурация и границы проверки

28 октября 2026 узкая read-only проверка Mac подтвердила папку Syncthing `obsidian-sync`, тип sendreceive, путь `~/Documents/DB1`, неприостановленное состояние и одного удалённого участника с именем Pixel. API использовался только через loopback; ключ оставался в памяти и не печатался/копировался. Личные заметки и база не читались. `99 - Assets` игнорируется; явного исключения Telemetry не обнаружено. Конфигурация не менялась.

Первый снимок показал peer disconnected, позднее в 17:19:31 UTC — connected, folder idle, needItems=0, pullErrors=0. На телефоне исполнитель отдельно увидел `Obsidian Sync` → `[int]/Documents/DB1-Sync`, «Актуальна», 388/388 и участника MacBook. Это проверка состояния клиентов и путей, **не доказательство доставки новых событий** и не обещание постоянной связи. Сон, ограничения Android, остановленный Syncthing и сеть могут задерживать обмен.

## Пространство файлов и приватность

Production:

```text
FocusDeck/Telemetry/v1/events/android/<producerUUID>/<sha256-bytes>.jsonl
```

Один producerUUID создаётся в `noBackupFilesDir` одной установки приложения и сохраняется между перезапусками. Другая установка/QA получает другой UUID; Mac только читает. Нет двух авторов одного producer-каталога.

Передаваемые поля — typed v1 metadata: идентификаторы события/сессии, UTC-время, work/study/unknown, lifecycle, уровень свидетельства, nullable метрики, временные границы, безопасные коды причины и устойчивые идентификаторы задач/окна. Тексты задач, дневник, название окна, URL, DNS-запросы, свободный outcome, секреты и неизвестные поля не копируются. `taskRef` сохраняется одинаковым v1 ID во всех каналах: он может быть читаемым slug и является **личными метаданными**, не анонимным идентификатором. Он остаётся в собственной личной папке и приватном промежуточном кеше; не включается в репозиторий или внешний отчёт. Хеширование ID без согласованной миграции не применяется: оно изменило бы payload прежнего eventId и сломало сопоставление/дедупликацию.

Пакет — UTF-8 JSONL, максимум 128 КиБ и 256 событий. Имя — SHA256 точных байтов с завершающим newline. Временная запись создаётся под `.part`, закрывается, читается обратно, проверяется и переименовывается. Если существующий SHA-объект имеет другое содержимое, он сохраняется для диагностики; очередь не подтверждается и файл не удаляется. SAF не обещает атомарность для всех провайдеров, поэтому Mac всегда заново проверяет имя/байты/схему и не считает половину записи валидной.

Android разрешает только существующий сохранённый SAF read+write grant. Для разрешения точного дочернего пути нужны имена каталогов, но содержимое заметок не открывается и рекурсивного обхода заметок нет. Нет автоматического выбора личного vault в QA.

## Очередь и автоматический цикл

`TelemetrySyncClient(context)`:

- `configure(rootUri, telemetryRoot=false, enabled=true)` — явное добровольное включение для существующего grant; `status`, `enabled`, `automaticRetryScheduled` показывают локальное состояние.
- `updateSnapshot(jsonl)` вызывается из того же Room/audit snapshot; записывает только новые immutable eventId и пытается опубликовать без ожидания доступности Mac.
- `retry()` и `TelemetrySyncJobService` повторяют локальную публикацию; JobScheduler назначается не чаще технического минимума 15 минут, persisted только после opt-in. Android Doze/force-stop/батарея могут отложить выполнение; это не точный будильник.
- `disable()` отменяет Job и выключает будущие записи, сохраняя очередь. Небэкапируемый marker не даёт восстановленной настройке из backup молча включить обмен на другой установке. Смена/отключение выбранного vault также отключает обмен в интеграции приложения.

Локальная очередь и индекс ID/hash лежат в `noBackupFilesDir/telemetry-sync-v1`. Пакет удаляется из pending только после проверки локальной SAF-копии; это **подтверждение записи в папку**, не receipt Mac. Падение между записью пакета и индексом восстанавливается при перезапуске; повтор уже опубликованного пакета идемпотентен. Лимиты: pending 32 МиБ, индекс 16 МиБ; переполнение/конфликт сохраняют исходный Room/аудит и очередь, а не выдумывают нулевую работу. Публикация, уже начатая до выключения, может завершить один файл; новые пакеты не начинаются.

Syncthing переносит эти файлы, когда оба клиента и сеть доступны. Он не запускается и не перенастраивается этим кодом. Ключ его API не нужен Android-клиенту или Mac-коллектору. Полное удаление приложения удаляет Job/local outbox; уже опубликованные пользовательские файлы остаются в vault по выбранной политике хранения. Удаление всех участников/клиентов прекращает автоматический обмен; скрытой переустановки нет. Автоматическое удаление immutable пакетов из личного vault пока не включено: срок их хранения — отдельный явно выбираемый параметр, не следует путать его с 90 днями локальных отчётов.

## Mac-коллектор и ежедневный обзор

```sh
python3 harness/vault_events.py --root "$HOME/Documents/DB1/FocusDeck/Telemetry/v1/events/android" --output "$HOME/Library/Application Support/FocusDeckHarness/inbox/android-syncthing.jsonl" --health-output "$HOME/Library/Application Support/FocusDeckHarness/inbox/android-syncthing-health.json"
```

Коллектор принимает только явно переданный `events/android`, UUID-подкаталоги и SHA-named batches, без рекурсивного обхода vault. Symlink/hardlink и меняющийся файл не считаются событием. Проверяются SHA, размер, число строк, общая v1 схема, source=android и privacy whitelist. Временные/конфликтные/неполные объекты видны как partial; идентичные eventId объединяются, конфликтующие версии полностью исключаются. Счётчики наблюдавшихся файлов — не нулевая работа при отсутствии источника.

В конфигурации локального обзора `vaultTelemetryRoots` содержит явные корни. Подготовка поддерживает `--vault-telemetry-root ABS`. Каждый запуск сопровождения собирает их в приватный кеш и включает в текущий/дневной обзор; `vaultSyncHealth` отдельно показывает missing/empty/partial/unreadable/observed. При временной недоступности пути предыдущий проверенный receipt сохраняется с отметкой cachedPriorReceipt; не объявляется свежей доставкой. Свежесть, clock_skew и nullable часы вычисляются общим механизмом. Наличие локальной копии не доказывает, что телефон сейчас подключён или что все его данные получены.

Для уже установленного обзора нужен явный `scheduler.py upgrade --directory ...`, чтобы runtime включил новый коллектор; `prepare` не перезаписывает действующие настройки. Loopback laboratory receiver при необходимости обновляется `receiver.py upgrade --directory ...`: сохраняются token/inbox/config, проверяется принадлежность задания, есть backup/rollback. Оба обновления не активируют ранее выключенную задачу и не меняют Syncthing.

## Изолированная проверка

QA использует отдельный пустой дочерний каталог **в уже синхронизируемом дереве**, например `FocusDeck/Telemetry/v1/qa-<UUID>`, с отдельным SAF-grant и `telemetryRoot=true`. Писатель создаёт только `events/android/<producerUUID>` под ним. Заметки QA остаются в вымышленном vault. Production-коллектор не спускается в `qa-*`; тестовый Mac-коллектор получает точный QA-root явно.

JVM-тесты проверяют batching, SHA/лимиты, перезапуск, падение до индекса, подтверждение, конфликт и разных производителей. Python-тесты проверяют частичную запись→полный пакет, дубли/конфликты, privacy/schema, symlink, отсутствие источника и сохранение ранее проверенного кеша. Это синтетические проверки. Для реальной готовности нужны отдельно зафиксированные: публикация через SAF, появление одинаковых байтов на Mac без USB-копирования, сохранение очереди после разрыва/перезапуска, повтор после сна/соединения и отключение добровольного обмена. До этих проверок не заявляется автономная доставка на устройстве.

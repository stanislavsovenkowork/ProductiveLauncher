# Цели и проекты: новый интерфейс — 29 сентября 2026

Прежние экраны (`ui/life/LifeScreen.kt`, 1358 строк стандартных форм) заменены. Слой данных, правила переходов, защита черновиков и конфликтов (`LifeRepository`, `LifeRules`, `LifeNoteCodec`, `LifeDraftCodec`) сохранены без изменения семантики.

## Путь пользователя

1. **Главная** → карточка «Цели и проекты»: проект, который движется сейчас, его процент и следующий шаг, число шагов за неделю, сигнал «Пора свериться».
2. **Компас** (обзор): пульс «шаги к целям» за 7 дней + тепловая карта 4×7 + «N из 4 недель в движении»; карусель внимания (сверки, решения к проверке, проекты без следующего шага, обзор недели с пятницы по воскресенье); цели кольцами; проекты в работе — процент по этапам, следующий шаг и кнопка «Сегодня» (одно касание → задача в дневной заметке); идеи и пауза свёрнуты; сферы чипами.
3. **Создание** — мастер по одному вопросу на экран, клавиатура сразу открыта, кнопка над клавиатурой. Проект: название → «готово, когда» → первый шаг (+ «сделаю сегодня/завтра») → этапы → связь с целью/сферой. Цель: название → почему важно → критерий → помеха → «если — то» → сфера и срок. Решение: вопрос → варианты → выбор → ожидание → дата проверки. Неполная запись сохраняется идеей (DRAFT), а не ошибкой.
4. **Деталь проекта**: кольцо прогресса, карточка следующего шага (не в плане / в плане · время / сделан → «что дальше?»), этапы-чекбоксы с сегментной полосой, шаги за 4 недели, «план на трудный момент» (помеха + если—то), решения, история сверок.
5. **Сверка** — один экран: вердикт чипом (продолжаю / меняю подход / пауза / готово / больше не планирую), одна фраза, следующий шаг, когда свериться снова.
6. **Завершение** проекта/цели, закрытие всех этапов — конфетти; отдельный этап — короткий тост.

## Прогресс — только измеренный

- Процент проекта = отмеченные этапы / все этапы (`## Этапы`, обычные `- [ ]`). Нет этапов — нет процента: карточка предлагает разбить на этапы.
- Процент цели = среднее по её вехам и измеримым проектам; завершённый проект = 100%.
- Шаги = задачи дневных заметок с `[project::]`/`[goal::]`/`[area::]`, отмеченные выполненными (одно чтение папки за 4 недели: `VaultRepository.readDailyNotes`).
- Пустые дни — нейтральные клетки. Вместо ломкой ежедневной серии — «недели в движении» (из последних 4).

## Obsidian

- Этапы — обычный чеклист в заметке проекта/цели: их можно отмечать в Obsidian, приложение прочитает. Строки вне чекбоксов в секции не трогаются.
- Задачи-шаги по-прежнему живут только в дневных заметках; проект хранит текст следующего шага, а не второй чекбокс.
- Новая секция появляется в заметке только после первого добавления этапа.

## Соответствие исследованиям (без обещания эффекта)

| Приём | Где в интерфейсе |
| --- | --- |
| Конкретная цель с критерием (Locke & Latham; Epton et al. 2017) | Шаг «Как поймёшь, что готово», карточка «Достигнута, когда» |
| Отслеживание прогресса (Harkin et al. 2016) | Этапы, кольца, тепловая карта шагов, сводка недели |
| Мысленное сопоставление + «если — то» (WOOP; Wang et al. 2021; Gollwitzer & Sheeran) | Шаги «Что помешает» / «Если — то», карточка «План на трудный момент» |
| Согласованность с собственными мотивами (Sheldon; Sezer et al.) | Вопрос «Почему это важно именно тебе?», цитата на детали цели |
| Следующее физическое действие (GTD) и малые победы (Amabile, Progress Principle) | Карточка следующего шага, «Задай следующий шаг», тост за этап |
| Ожидание решения до результата | Прогноз от даты принятия показывается перед вводом факта |

### Второй проход: добавлено по `life-system-evidence.md`

| Приём | Исследование | Что в интерфейсе |
| --- | --- | --- |
| Время старта как часть намерения | Gollwitzer & Sheeran 2006 (d = 0,65); Sheeran et al. 2024 | «Когда начнёшь?» (утро/день/вечер/время) при планировании шага; «если — то» показано у следующего шага и на Главной |
| Премортем / проспективная ретроспектива | Mitchell, Russo & Pennington 1989; Klein 2007 | Вопрос о помехе: «Представь: срок прошёл, не вышло. Что помешало?»; шаг «помеха → если — то» в мастере проекта |
| Числовой показатель цели | Harkin et al. 2016 (d = 0,40, сильнее при записи) | Секция `## Показатель` (`Цель: 21 км`, `Старт: 5`, `- дата: значение`), крупная цифра, спарклайн, замер в одно касание; входит в кольцо цели |
| Автономный мотив | Sheldon & Elliot 1999 | Чипы «интересно / важно мне / чувствую, что должен / ждут другие» (строка `Мотив:` в «Почему»); при «надо» — мягкий вопрос в мастере и на сверке |
| Подача прогресса: сделано → осталось | Koo & Fishbach 2012 (small-area) | До середины «пройдено N из M», после — «осталось N этапов» |
| Взгляд снаружи против ошибки планирования | Buehler, Griffin & Ross 1994 | Дата закрытия этапа (`✅ YYYY-MM-DD`, формат плагина Tasks) → «темп X в неделю → финиш ~дата · позже срока / успеваешь»; то же по показателю |
| Калибровка прогнозов | Mellers et al. 2014; Tetlock | Уверенность 50–90% при принятии решения, «ожидание сбылось: да/частично/нет» при проверке; карточка калибровки в «Решениях» |
| Незакрытые петли | Masicampo & Baumeister 2011 | Проект без шагов 14+ дней → карточка «Без шагов N дн» → сверка (продолжить / изменить / пауза) |
| Эффект нового старта | Dai, Milkman & Riis 2014 | В понедельник — «Новая неделя · разобрать прошлую» (обзор завершённой недели, с полными фактами) |

Все новые данные — читаемые строки Markdown внутри существующих секций: их можно писать и в Obsidian.

Геймификация намеренно без очков и уровней (риск подмены внутренней мотивации): только факты — кольца, клетки, празднование реального завершения.

# Восстановление сайтов, Mac 0.12.2 / build 17, 5 ноября

Пользователь сообщил, что Chrome перестал открывать сайты, и показал ERR_SOCKET_NOT_CONNECTED на Google. Ошибка подтверждена: прокси FocusDeck вернул 502 для www.google.com, прямой запрос в тот же момент получил 200. Затем после автоматического перезапуска службы запросы временно снова проходили.

Причина найдена в выполнении служебных команд через Foundation Process/Pipe. Каналы не закрывались явно и накапливались в долгоживущем процессе. В живой службе PID 24731 было 290 PIPE-дескрипторов, через 2 секунды стало 294. В журнале были падения с errno 24 / Too many open files при записи защищённого состояния. Перезапуск обрывал прокси, а исчерпание ресурсов мешало открывать новые соединения. Предыдущая проверка только CONNECT 200 не проверяла передачу страницы и не обнаружила накопление ресурсов.

## Что изменено и установлено

- `ServiceCommand.run` закрывает оба конца stdout/stdin Pipe при успехе, ненулевом завершении и ошибке запуска. Вызов и каждый проход службы имеют autoreleasepool.
- Только у LaunchDaemon FocusDeck установлен мягкий лимит 4096 файлов. Это запас для браузерных соединений, а не замена исправления утечки. Глобальные лимиты не менялись.
- Прокси ограничивает число одновременно обслуживаемых клиентов до 512, ставит 15-секундный таймаут записи и повторяет прерванные poll/send.
- Сохранены проверка доменов/адресов, полный набор параметров защищённого Chrome и исправления распознавания 0.12.1.

Установлено `/Users/stanislav/Applications/FocusDeck System.app`, версия 0.12.2, build 17. SHA-256 установленного root-помощника совпал со сборкой: `62ef611dc002993e2b87690e4b680215057d1bda07ab62b9131830bbaf8c4e8f`. Новый PID службы 28104; Chrome остался PID 483. Сохранилось активное окно `035A4235-6E83-44AB-8628-7A2AC89534F5`, его цели и остаток срока. Профили Chrome, входы, телефон, корпоративные VPN и маршруты этим обновлением не менялись.

## Проверенный результат

- Регрессионная проверка выполнила 400 команд с передачей stdin, ненулевым завершением и отсутствующим исполняемым файлом при лимите процесса 128 дескрипторов. Открытых дескрипторов до/после: 3 → 3.
- В установленной службе за 40 секунд во время браузерной проверки: всего дескрипторов 50, 48, 34, 33, 33; PIPE 0, 0, 0, 1, 1. PID не менялся. Линейного накопления, наблюдавшегося до исправления, нет в этом замере.
- Через установленный прокси полностью скачаны HTML Google (86 271 байт), Example (577) и ChatGPT (656 061), HTTP 200. Это больше, чем проверка одного CONNECT.
- В реальном открытом Chrome через computer use Google и Example показали содержимое после трёх обновлений каждый; Wikipedia также открылась с содержимым. Личные вкладки и профили не закрывались. Example оставлен открытым, поскольку пользователь взаимодействовал с браузером и принадлежность вкладки больше нельзя было надёжно определить.
- Instagram, TikTok, YouTube, YouTube Music, Reddit и X получили от установленного прокси 403. В Chrome YouTube не открылся; один браузерный код ошибки сам по себе не доказывает причину, её подтверждает отдельный ответ 403 прокси.
- Служба сообщила `networkActive=true`, `dnsActive=true`, активное прежнее окно. Повторного запуска/сокращения окна не выполнялось.

Сборка, прежнее установленное приложение и краткие результаты находятся в `outputs/FocusDeck-Mac-0.12.2-20261105/`: `confirmed-leak-before.json`, `before-update.json`, `after-update.json`, `root-fd-observation.json`.

Короткий замер и проверка браузера не доказывают отсутствие любых будущих сетевых ошибок. Причина отдельного внутреннего SIGTRAP ChatGPT из предыдущего разбора этим исправлением не установлена. Защита от произвольных самодельных клиентов и час задержки против владельца с root по-прежнему не объявляются доказанными.

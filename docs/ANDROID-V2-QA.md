## Без экрана: хранилище и export

После проверки scope и подписи, в отдельном QA-пакете:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e action protection-ledger dev.stanislav.focusdeck.qa.test/dev.stanislav.focusdeck.qa.VaultProbeInstrumentation
adb shell am instrument -w -e action scheduled-protection dev.stanislav.focusdeck.qa.test/dev.stanislav.focusdeck.qa.VaultProbeInstrumentation
```

`protection-ledger` использует отдельные свежие preferences и синтетические часы; ожидаемый результат `status=ok` и `atomic_recovery_same_day_budget`. Он проверяет отказ атомарной записи, сохранение ID/даты, категории, QA-целей, конца и расхода после перезапуска; изменение расписания не подменяет активное окно, отключение будущего расписания сохраняет окно и ожидание выхода. Также проверяются дневной бюджет после выхода и нового включения, immediate opt-in и ожидание при неизвестной загрузке. `scheduled-protection` ожидает `status=ok`, `recurring_isolated_restore_cancel`; он проверяет восстановление расписания и сериализацию исключительно синтетических событий. Сохранить фактический вывод, не выдавать сборку или тест модели за эти результаты.

Строгий режим **недоступен для пользовательского включения**: после перезагрузки без доверенного времени нельзя одновременно гарантировать прежний конец окна и защиту от подмены часов. Только изолированный `protection-ledger` может включить экспериментальную политику и проверяет отказ в послаблении, сохранение ограничений во время отдыха и выход по синтетическим часам. Экспериментальное восстановление переякоривает ранее активное окно на его исходную длительность и может продлить его за согласованный конец; это не выполнение пользовательского требования. Проверка сохранённого состояния ещё не запускалась на Pixel. Настоящее ограничение зависит от работающей Accessibility; без подтверждённого управления устройством владелец может отключить службу или удалить приложение. Не считать локальный тест либо сборку доказательством системной защиты.

## Ограниченная UI-проба выбранного приложения

Выполнять только когда пользователь не пользуется устройством. Следовать правилам computer use и системным подтверждениям при предоставлении Accessibility; не включать её скрыто. Использовать **только** `FocusDeck QA Probe` из `dev.stanislav.focusdeck.qa.test`, проверить его пакет перед выбором. Другие приложения не выбирать. Служба Accessibility — только для `.qa`; если она не подключена или устройство недоступно, системный контроль считать непроверенным.

1. В QA отметить только QA Probe для выбранной категории. Создать окно «Без браузеров/лент» на сегодня после 15:00 Europe/Minsk, с коротким фиксированным концом. Сверить видимое имя и идентификатор выбранного пакета; не выбирать реальные браузеры. Если текущее время не позволяет создать короткое окно в этом же дне, не менять системные часы.
2. Зафиксировать доступность Probe до начала. В активном окне открыть Probe с домашнего экрана Android и наблюдать реальный возврат на Home; проверить событие `system_app_denied` с UUID окна. Отдельно проверить попытку через FocusDeck и `launcher_attempt_denied`. Отсутствие событий или другой foreground — не PASS.
3. Выбрать ограниченное послабление; попытка открыть Probe должна пройти. Явно вернуться, повторить попытку и наблюдать ограничение. Завершить по естественному концу окна и проверить, что Probe открывается; отдельно проверить полный выход после показанного ожидания. Остановка таймера и новая задача не должны сбросить бюджет или ожидание.
4. Убедиться, что завершение теста не меняет личную базу, выбор личного VPN или Private DNS. Убрать только временно выданные QA-разрешения штатными средствами, если они выдавались для этой пробы. Записать точные наблюдения, время, версию и хэши; не объявлять полную системную защиту по одной цели.

DNS-проба — отдельная задача: требует отдельного пользовательского выбора и штатного системного согласия на VPN. Текущий кандидат не запускается автоматически, отказывается при обнаружении другого VPN или активного Private DNS и покрывает только DNS через выбранный VPN-резолвер по IPv4 UDP для выбранных приложений. DoH/DoT, собственный DNS, прямые IP, IPv6 и кэш могут обходить фильтр. Прежний QA DNS round-trip не подтверждает новое календарное окно или восстановление сети текущей сборки.

## Диагностика подключения службы

Только после отдельной изолированной QA-сборки и согласованного доступа к устройству: при штатном включении QA Accessibility наблюдать `adb logcat -v brief -s FocusDeckGateQA:I '*:S'`, не очищая общий журнал. В debug-пакете маркеры `service_connected_callback`, `audit_enqueued`, `room_ready`, `room_error class=<класс>` и `service_destroyed` не содержат текста исключения или данных события; release-вариант ничего не пишет. Проверять время и процесс текущей пробы: буфер может содержать старые сообщения или терять записи. Отсутствие маркера само по себе не доказывает отсутствие вызова. Сопоставить маркеры со статусом UI и фактической пробой QA Probe; только `room_ready` не доказывает системного ограничения. По окончании штатно отключить только временное QA-разрешение и проверить очистку расписания и окна. При недоступности устройства не менять USB или сеть для восстановления.

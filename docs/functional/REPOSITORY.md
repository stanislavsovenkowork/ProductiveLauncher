# Состав репозитория и происхождение

## Назначение

Приватный репозиторий: **[stanislavsovenkowork/ProductiveLauncher](https://github.com/stanislavsovenkowork/ProductiveLauncher)**. Аккаунт, адрес и private-видимость подтверждены через GitHub. Это явно выбранное пользователем место, а не корпоративный GitLab и не другой личный GitHub-аккаунт.

## Как объединён срез

Исходная локальная история оканчивалась коммитом `2007e7a74bf8d42c67aa19cd6d83140ffd98b944` и содержала 29 коммитов. К ней не были добавлены все последние исходники/документы.

В основной Desktop-копии находились важные незакоммиченные изменения и отдельный Atlas. В рабочей копии находились Mac/harness/shared/integration и более новые Android/Obsidian исходники. Общие изменённые файлы кода сравнивались с сохранённым baseline: Desktop совпадал с ним, рабочая копия содержала последующее изменение. Поэтому взяты более новые версии без перезаписывания исходных рабочих областей.

Для отличавшихся документов отдельно проверены сохранность содержания и даты: новый implementation log содержит Desktop-текст целиком, статус дополнен исправлениями Mac 0.12.1/0.12.2, Android QA уточнён более поздними условиями. Актуальные карточки бэклога 3–7 сохранены. Старые отчёты остаются историей, не выдаются за текущее руководство.

Публикуется объединённый проверенный срез. Новая функциональная документация находится в [этом каталоге](README.md); исходные рабочие области не подвергаются reset/clean. Для операций GitHub используется уже подключённое приложение; отдельный новый SSH-доступ не требуется.

## Старая Git-история

[history/legacy-git.bundle](../../history/legacy-git.bundle) содержит точную исходную цепочку 29 коммитов и проверен `git bundle verify`. Это архив прежней истории, а не утверждение, что новые GitHub-коммиты получили прежние SHA.

Восстановление в отдельную папку:

```sh
git clone history/legacy-git.bundle FocusDeck-legacy
```

После этого старый `main` доступен для просмотра/сравнения. Незакоммиченные изменения двух исходных рабочих областей объединены в текущем дереве репозитория, а не находятся внутри старого bundle. Личные рабочие папки и их не предназначенные для публикации данные остаются на Mac.

## Что включено

Android `app/guard/gradle`, Swift-код и ресурсы `macos-study`, три файла Obsidian-плагина, shared-контракты, harness/integration, тестовые исходники, обезличенные fixtures, build scripts, документы функций/планов/ограничений и вспомогательный исходный Atlas. Наличие legacy/QA кода не означает его включение в личной среде.

## Что не включено и почему

| Категория | Причина |
|---|---|
| Личный Obsidian vault, дневники, задачи и `.obsidian` пользователя | Это данные пользователя, а не код интеграции |
| `local.properties`, `keystore.properties`, keystore/private keys, реальные токены и пароли | Локальная настройка и учётные данные |
| Room/SQLite базы, browser profiles/cookies/login storage, root-ledger и журналы установленных приложений | Личные runtime-данные вне проекта |
| `.agents/history`, дубли памяти, локальный MCP config | Личные переписки и настройки подключений, не функциональная документация |
| Gradle/Kotlin/npm/Roslyn/Atlas caches, `bin/obj/dist/build`, `.atlas`, `.openai` | Воспроизводимые результаты или локальное размещение |
| APK/AAB/APP/DMG/ZIP, большие QA outputs и временные пробы | Собираются из исходников; старые личные доказательства не публикуются автоматически |

Версионируемые иконки и Gradle wrapper JAR оставлены как необходимые входные ресурсы сборки. В source fixtures допускаются только обезличенные данные. Публикация не создаёт релизных бинарников и не подменяет ключ подписи Android.

## Проверка полноты

Файлы выбранного среза перечисляются в [SOURCE-MANIFEST.json](SOURCE-MANIFEST.json) с SHA-256 и происхождением. Сам manifest и генерируемые результаты проверок отдельно от исходного списка; новые документы перечислены в навигации. Итог проверки и удалённого дерева — [VERIFICATION.md](VERIFICATION.md).

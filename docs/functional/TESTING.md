# Проверки проекта

## Принцип

Проверять исходники и синтетические данные отдельно от личных устройств/заметок. Успех компиляции не равен установленной защите, отрисовке UI или доказанной пользе. Итоги именно этой публикации — [VERIFICATION.md](VERIFICATION.md); старые проверки остаются датированными отчётами.

## Android

```sh
./gradlew :app:testDebugUnitTest :guard:testDebugUnitTest
```

JUnit/XML-результаты находятся в `app/build/test-results/testDebugUnitTest/` и `guard/build/test-results/testDebugUnitTest/`. Эти файлы генерируются и не входят в исходники. Набор тестов не следует изменять ради зелёного результата.

Instrumentation в `app/src/androidTest/` относится к отдельному QA-пакету и согласованной отдельной тестовой папке. Его сборка/запуск не являются разрешением читать или перезаписывать личный vault. Сохранённый [ANDROID-V2-QA.md](../ANDROID-V2-QA.md) содержит исторические процедуры собственной защиты; текущий личный Android-режим использует Stay Focused и не требует их повторения.

## Mac

Сборка основной конфигурации:

```sh
bash macos-study/build-system-app.sh
```

Узкий регрессионный тест жизненного цикла служебных Pipe запускается без root и меняет лимит дескрипторов только своего процесса:

```sh
xcrun swiftc -swift-version 6 -parse-as-library \
  macos-study/system-protection/ServiceCommand.swift \
  macos-study/system-protection/tests/ServiceCommandTests.swift \
  -o /tmp/focusdeck-service-command-checks
/tmp/focusdeck-service-command-checks
```

`ManagedBrowserTests.swift` дополнительно ожидает уже работающий защищённый Chrome и проверяет read-only discovery; это не универсальный тест чистой машины. `CommitmentTests.swift` проверяет синтетический сохранённый срок/выход. Другие advanced-lab сценарии могут иметь системные действия: их нельзя считать безопасным общим `test all` на личном Mac.

Для реальной проверки сайта нужен полный HTTP/TLS обмен и отрисовка разрешённой страницы, а не один CONNECT 200. Для запрета отдельно нужны точная выбранная цель и отказ её загрузки. Проверять нужно также совместимость с рабочей сетью. Публикация исходников не запускает новые root/PF/VPN/reboot пробы.

## Obsidian и форматы

```sh
node --check obsidian-plugin/focusdeck-panel/main.js
```

Это синтаксис JavaScript, не тест UI Obsidian. Поведение записи проверять на обезличенной копии заметки с устойчивыми ID, одинаковыми заголовками, внешними изменениями и конфликтами. Историческая связка реальных устройств описана в [SEAMLESS-SYNC-20261104.md](../SEAMLESS-SYNC-20261104.md); один её замер не является гарантией задержки доставки.

Общие схемы и проверки: [shared/README.md](../../shared/README.md), `shared/validate_events.py`, `integration/`. Atlas имеет отдельный `npm test`; его результаты не означают проверку лаунчера.

## Документация и публикация

Перед отправкой сверить полный Git-список с исходниками обеих рабочих областей, проверить относительные ссылки/якоря новых руководств и сохранить действующий бэклог. Секреты и личные runtime-данные исключаются до загрузки. Удалённое дерево и SHA файлов после публикации сверяются независимо; одного успешного ответа upload недостаточно.

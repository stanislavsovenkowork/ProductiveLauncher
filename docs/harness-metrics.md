# Локальный цикл измерений и возврата

`harness/metrics.py` — вызываемый вручную локальный сборщик и ежедневный обзор на Python 3 без сторонних библиотек. Он читает только явно переданные JSONL и пишет отдельный JSON-отчёт. Подготовка ежедневной локальной проверки описана ниже; установка фоновой задачи и внешние сообщения не выполняются. Схема событий: `shared/event-v1.schema.json`.

```sh
python3 harness/metrics.py cycle --events /absolute/export/events.jsonl --day 2026-11-02 --output /absolute/reports/2026-11-02.json
python3 -m unittest discover -s harness/tests -v
```

Можно передать несколько `--events`: экспорт Mac и Android. Отсутствующий файл отражается как `missing`, битые и неподдерживаемые строки — в `invalid`. Идентичный `eventId` учитывается один раз. Конфликтующие версии одного `eventId` целиком исключаются и выводятся в `conflictingEventIds`. Отчёты используют календарные сутки `Europe/Minsk` по умолчанию; `--timezone` принимает зону IANA. Поля `day`, `timezone`, `windowStartUTC`, `windowEndUTC` фиксируют границы. Переходы летнего времени учитываются через `zoneinfo`. События принимают UTC как `Z` или `+00:00`. Сам отчёт может содержать текст результата пользователя: храните его в выбранном личном каталоге, не в репозитории.

Основной показатель — часы фокуса отдельно для работы и учёбы, с разделением `timer`, `activity`, `self_report`, `verified`, `unknown`. Таймер и активность являются приближением, а не доказательством полезного результата. Подтверждение результата и самоотчёт выводятся отдельно в `outcomes`; сборщик не проверяет утверждения пользователя. Поле `verified` может выставлять только источник, имеющий основание для проверки.

Для часов нужны начало и конец неперекрывающего паузы интервала и измеренное `focusSeconds`, совпадающее с длиной интервала. События с длительностью без временных границ видны как `unpositionedFocusRecords`, но не увеличивают основной показатель. Перекрытия устройств внутри категории объединяются; более сильное свидетельство занимает перекрытый участок, не добавляя часы повторно. Перекрытие работы и учёбы либо неизвестной категории исключается из категорий и показывается как `ambiguousFocusSeconds`. Это консервативная оценка, не полное время полезной работы. Чтение без ввода не считается отвлечением.

В обзор входят наблюдавшиеся сессии, завершения, остановки, пропуски, явные отключения/удаления, измеренные отвлечения и обслуживание. Для отвлечений и обслуживания `reportedMetrics` — сумма переданных измерений, а не объединённая длительность между устройствами: источникам нельзя присылать перекрывающиеся измерения этих полей. Неизмеренное значение — `null`, а не ноль. Явно измеренный `focusSeconds: 0` сохраняется как известный ноль, включая интервал нулевой длины. Нули в счётчиках означают ноль *наблюдённых событий*, не доказанное отсутствие работы или отказа. Полнота входа выводится по каждому источнику; покрытие всего дня и доля удержания без известного расписания/знаменателя не вычисляются.

## Адаптер MoveBreak

```sh
python3 harness/metrics.py cycle --movebreak "$HOME/Library/Application Support/MoveBreak/movebreak-events.jsonl" --movebreak-category study --day 2026-11-02 --output /absolute/reports/2026-11-02.json
```

Адаптер изучен по исходнику `mac-usage-dashboard`, без чтения личного журнала или базы. Файл читается только при явном запуске команды. Поддерживаются `block_completed` с измеренным `focusSeconds` или `actualSeconds` и UTC-датой `at`/`createdAt`. Плановые `minutes`, активный `current-session.json` и остальные события не добавляют часы. Категория по умолчанию неизвестна (`--movebreak-category unknown`, в событии `null`); её можно явно задать для всего импорта только при достоверной разметке. Смешанный журнал остаётся без категории или предварительно размечается в общей схеме. Текст задачи не используется для угадывания категории.

Интервал восстановлен назад от времени завершения на измеренную длительность: `intervalEstimated=true`. Реальное расположение пауз неизвестно: такие интервалы исключены из основного объединения часов и показываются отдельно как `estimatedFocusSecondsByEvidence`. Эти значения нельзя прибавлять к часам других устройств; для них нет надёжного расположения во времени. События с одинаковым содержимым получают стабильный UUID. Адаптер ничего не пишет в MoveBreak или Obsidian.

## Будущий эксперимент и возврат

```sh
python3 harness/metrics.py protocol --start 2026-11-02 --end 2026-11-16 --output /absolute/protocol-draft.json
```

Даты в примере — пример явных будущих границ, не рекомендация оптимальной длительности. Команда требует будущую дату начала и более позднюю дату конца, создаёт заблокированный черновик. До эксперимента необходимо заполнить гипотезу, исходные даты сравнения, критерии продолжения/изменения/отказа и бюджет обслуживания. Этот инструмент не активирует эксперимент и не заявляет научно доказанную дозу.

Независимый канал добровольного возврата после удаления **обязателен до запуска эксперимента**: выбор пользователя, согласие и условия остановки напоминаний, срок хранения и процедура восстановления контекста. Здесь он не настроен. Полное удаление всех компонентов не позволяет выполнить этот локальный скрипт. Отсутствие heartbeat означает неизвестное состояние; оно не доказывает удаление, отказ или нулевую работу. Отчёт предлагает начать одну выбранную задачу без длинного отчёта и задолженности. Доставка этого предложения после удаления пока не реализована.


## Ежедневная локальная проверка: подготовлено, не установлено

```sh
python3 harness/scheduler.py prepare --directory "/absolute/private/FocusDeckReview" --events "/absolute/export/mac-events.jsonl" --events "/absolute/export/android-events.jsonl" --protocol "/absolute/private/protocol-draft.json"
```

Для ежедневного чтения MoveBreak можно добавить `--movebreak /absolute/path/movebreak-events.jsonl --movebreak-category study`; категория должна быть известна для всего файла.

Команда создаёт `review-config.json` с `enabledByUser=false` и `local-review.plist` в выбранном приватном каталоге, вне репозитория и вне `LaunchAgents`. Все пути абсолютные. Каталог имеет права `0700`, конфигурация и отчёты — `0600`. Внешние сообщения не отправляются. Команда не вызывает `launchctl` и не активирует расписание.

Для добровольного включения после проверки конкретных источников предусмотрена команда `install` ниже. Она включает конфигурацию, устанавливает только собственный plist и запускает локальную проверку. Факт установки подтверждается отдельно результатом `status`; наличие исходников не означает установленный процесс. Можно проверить один запуск вручную:

```sh
python3 harness/scheduler.py run --config "/absolute/private/FocusDeckReview/review-config.json"
```

Runtime копируется в `<directory>/runtime` вместе с общей схемой/валидатором и SHA256-манифестом. Исполнение не зависит от сохранения рабочего дерева. Повторная `prepare` сохраняет существующую конфигурацию и завершается с ошибкой; выберите новый каталог для обновления после остановки старого экземпляра.

Задача подготовлена для запуска при загрузке пользовательского агента/входе и ежедневно в 09:00 по системному времени Mac; границы отчётного дня используют настроенную зону независимо от часового пояса Mac. После включения каждый запуск создаёт отчёт за предыдущие календарные сутки и `latest.json`. `dailyCheck` показывает отсутствие данных, устаревание последнего события (настраиваемые `staleAfterHours`, по умолчанию 36), полноту чтения каждого источника и источники, требующие внимания. Недоступный файл не трактуется как нулевая работа. Наличие свежего сигнала одного устройства не скрывает отсутствие другого источника.

`protocolReview` вычисляет наступление даты окончания и список незаполненных условий протокола; это локальный статус необходимости обзора, а не доказательство успешного эксперимента. При отсутствии данных отчёт всё равно создаётся. После сна Mac launchd может выполнить пропущенное календарное задание после пробуждения; заполнение всех пропущенных дней и удалённая доставка уведомлений не реализованы. Еженедельный локальный обзор запускается в понедельник или при первой последующей проверке, если обзор этой недели отсутствует; сохраняет критерии протокола, полноту семи предыдущих дней и часы по уровням доказательности. Пропавший/битый дневной отчёт виден как неизвестные данные. Доля дней с измерениями не равна полноте наблюдения внутри дня; автоматически объявлять пользу по ней нельзя. Датированные дневные и недельные отчёты удаляются через 90 дней, настраивается `retentionDays`; конфигурация, runtime и два последних обзора сохраняются до явного удаления.

`recovery.lastKnownSessionState` учитывает последнее наблюдённое начало/возобновление/паузу/завершение/отключение; позднее `started` или `resumed` заменяет старое `stopped`. `observation` отдельно показывает свежесть наблюдений. Heartbeat не возобновляет остановленную сессию. `currentSessionState` остаётся `unknown`: история событий не доказывает текущее состояние без живого снимка. Раннер не читает `current-session.json` и не утверждает, что отсутствие данных означает удаление.


## Установка, проверка и удаление локального агента

После подготовки выбранного приватного каталога:

```sh
python3 harness/scheduler.py install --directory "$HOME/Library/Application Support/FocusDeckHarness"
python3 harness/scheduler.py status --directory "$HOME/Library/Application Support/FocusDeckHarness"
python3 harness/scheduler.py uninstall --directory "$HOME/Library/Application Support/FocusDeckHarness"
```

`install` проверяет хеши runtime, не перезаписывает чужую задачу, включает локальную конфигурацию и использует `bootstrap`/`kickstart` в пользовательском launchd. `status` показывает наличие задания, состояние launchd и наличие локального отчёта. После перезапуска процесса восстановление идёт из той же конфигурации и каталога отчётов. Эти команды не отправляют внешних сообщений.

`uninstall` останавливает только принадлежащую выбранному каталогу задачу, удаляет её plist и выключает конфигурацию. Отчёты и контекст сохраняются в выбранном каталоге; их можно удалить отдельно после проверки. Скрытой переустановки нет. Полное удаление и приложения, и независимого каталога/агента прекращает автоматические проверки. Сохранённый локальный агент может обнаружить отсутствие экспортов, но не доказывает удаление приложения и не доставляет напоминаний вне компьютера.

## Автоматическая доставка событий в локальный приёмник

`harness/receiver.py` — отдельный приёмник стандартной библиотеки Python. Он слушает **только `127.0.0.1:48731`**. Публичный/LAN bind отклоняется. Подготовка создаёт случайный токен и конфигурацию с правами `0600` вне репозитория, runtime с SHA256-манифестом и отдельный plist; токен не печатается.

```sh
python3 harness/receiver.py prepare --directory "$HOME/Library/Application Support/FocusDeckHarness/receiver"
python3 harness/receiver.py install --directory "$HOME/Library/Application Support/FocusDeckHarness/receiver"
python3 harness/receiver.py status --directory "$HOME/Library/Application Support/FocusDeckHarness/receiver"
python3 harness/receiver.py uninstall --directory "$HOME/Library/Application Support/FocusDeckHarness/receiver"
```

Установка отдельная и проверяет принадлежность задания и хеши runtime. `uninstall` останавливает приёмник и сохраняет токен/историю; полное удаление приватного каталога выполняется отдельно при явном отказе от сохранения контекста. Повторная подготовка не затирает конфигурацию или существующий токен. HTTP-запросы, URL, токены и тексты событий в логи не записываются.

Контракт для приложений:

- `POST /v1/events`; `Authorization: Bearer <token из tokenFile>`; `Content-Type: application/json`.
- Тело: `{"schemaVersion":1,"events":[<событие v1>,...]}`. Все события одной партии имеют один `source`; максимум 256 событий и 128 КиБ. Каждый объект проходит общий строгий валидатор.
- `202` возвращает только `accepted` и `duplicates`. Повтор идентичного `eventId` идемпотентен. Конфликт ID возвращает `409`, вся партия отклоняется. Некорректные события — `400`, отсутствие авторизации — `401`, превышение тела — `413`, недоступное хранилище — `503`. Источник должен сохранять неподтверждённую очередь и повторять её после восстановления связи.
- Авторизованный `GET /v1/health` показывает только количество и время последнего события по источникам; тексты задач не возвращает. Нет CORS, LAN-доступа или внешних сообщений.

Файлы приёмника: `<receiver>/inbox/{mac,android,movebreak}-events.jsonl`. Запись атомарная с блокировкой между потоками/процессами, права `0600`; конфликт проверяется между всеми источниками. Эти файлы принадлежат приёмнику: другим компонентам нельзя дописывать их напрямую. Нативный Mac-компонент пишет отдельный `FocusDeckStudy/events.jsonl`; ежедневный сборщик может читать оба пути. Лимит — 32 МиБ на источник. События старше согласованного `retentionDays` (по умолчанию 90) отклоняются, принятые старые записи удаляются при часовом обслуживании/обращении к health. Отсутствие или ошибка доставки остаются пробелом данных.

Android может обращаться к тому же loopback-порту через **явно настроенный пользователем USB/ADB reverse** (`adb reverse tcp:48731 tcp:48731`). Это не открывает порт в локальную сеть и не является постоянной связью телефона вдали от Mac: после потери подключения события должны оставаться в локальной очереди. Перед настройкой нужен явно выбранный способ передачи токена в приложение; токен не следует добавлять в репозиторий, экранные отчёты или журналы команд. Сам приёмник не включает ADB и не меняет телефон.

## Пассивный контекст Mac

`harness/native` содержит отдельный Swift/AppKit-наблюдатель. Он получает только bundle ID переднего приложения через `NSWorkspace`, переходы приложений и сигналы сна/пробуждения/неактивной пользовательской сессии. Нет чтения заголовков окон, URL, содержимого, нажатий, буфера обмена или сетевой отправки. Название приложения не используется для классификации работы/учёбы.

```sh
harness/native/build.sh /tmp/focusdeck-observer-build
python3 harness/native/control.py prepare --directory "$HOME/Library/Application Support/FocusDeckHarness/context" --binary /tmp/focusdeck-observer-build/FocusDeckContextObserver --session-snapshot "$HOME/Library/Application Support/FocusDeckStudy/session.json"
python3 harness/native/control.py install --directory "$HOME/Library/Application Support/FocusDeckHarness/context"
python3 harness/native/control.py status --directory "$HOME/Library/Application Support/FocusDeckHarness/context"
python3 harness/native/control.py uninstall --directory "$HOME/Library/Application Support/FocusDeckHarness/context"
```

Подготовка копирует бинарник в приватный каталог и сохраняет хеш; установка проверяет принадлежность и целостность. `observer-events.jsonl` — отдельный источник для ежедневного сборщика. Наблюдатель не обнаруживает глобальный приёмник и не пишет в его inbox. Конфигурация и бинарник сохраняются после удаления задания, скрытого восстановления нет.

Событие v1 имеет `type=health`, `evidence=activity`, а все три `metrics` — `null`. В `context` отдельно записываются bundle ID, наблюдённые секунды контекста и неизвестные промежутки. Это **контекст переднего приложения**, не сосредоточенные часы и не доказательство работы. Отсутствие ввода, в том числе чтение, не объявляется бездействием или отвлечением.

Сборщик закрывает контекст при смене переднего приложения и примерно каждые 30 секунд. Интервал свыше 45 секунд, разрыв системного/календарного времени и известный сон/неактивная сессия становятся `unknownGapSeconds`; непрерывное наблюдение через них не выдумывается. Значения 30/45 секунд — параметры технического семплирования, не научные нормы продуктивности. В момент старта состояние блокировки экрана неизвестно; `collectorAvailable` означает отсутствие полученного сигнала неактивности, а не доказательство присутствия человека.

По умолчанию категория и sessionId неизвестны. Только явно переданный `--session-snapshot` позволяет связать контекст с одной и той же активной сессией на обоих концах интервала: `phase=running`, валидные UUID/категория и `lastTick` не старше 10 секунд. Даже тогда фокус не вычисляется. Снимок читается только по указанному пути; `taskTitle`, `taskRef` и заметки в контекст не переносятся.

Журнал имеет права `0600`, каталог — `0700`, один пишущий процесс защищён файловой блокировкой. Срок хранения контекста по умолчанию 7 дней, размер ограничен 16 МиБ; при недоступной/переполненной записи процесс завершается, а здоровье источника становится устаревшим. Содержимое в stdout/stderr не сохраняется; состояние процесса доступно через launchd. Swift-тесты используют вымышленные bundle ID; `--fixture` читает только явно переданный файл и пишет только явно указанный журнал, без инициализации AppKit или поиска личной конфигурации.

Для точечного удаления ошибочной QA-сессии из inbox приёмника предусмотрена явная команда `receiver.py remove-session --config ABS --session-id UUID`. Она блокирует приёмник тем же файловым lock, удаляет только совпадающий sessionId, пишет атомарно и сохраняет приватную резервную копию в `.maintenance`, которую сборщик не читает. Команда не ищет сессии по тексту и не удаляет другие события. При необходимости полного удаления этих резервных копий требуется отдельное явное действие.

## Контекст в обзоре, текущий день и обновление runtime

`contextObservation` объединяет пересекающиеся интервалы наблюдённого контекста отдельно для `work`, `study`, `unknown` и по источникам; переход между инструментами внутри сессии не удваивает время. Перекрытие противоречащих категорий относится к неизвестной категории. `observedUnionSeconds` не является фокусом, рабочим временем или полезным результатом. Bundle ID и последовательность приложений в сводку не переносятся. `readingAssessment=unknown`: по бездействию клавиатуры чтение не определяется.

`unknownGapSecondsReported` и разрывы по источникам показываются отдельно; эти значения могут перекрываться между устройствами. Полного знаменателя покрытия пока нет (`coverageDenominator=null`). Сон, разрыв часов и отзыв доступа не превращаются в нулевую работу. Некорректные контекстные интервалы отражаются как `discardedContextRecords` и не увеличивают наблюдённое время.

Каждый запуск локального сопровождения сохраняет ещё и `reports/current-day.json` — текущий календарный день в настроенной зоне с `isPartialDay=true` и `generatedAtUTC`. Он предназначен для чтения интерфейсом Mac. При необходимости явного обновления:

```sh
python3 harness/scheduler.py current --config "$HOME/Library/Application Support/FocusDeckHarness/review-config.json"
```

Обновлённый локальный агент дополнительно запускается примерно каждые 300 секунд, помимо запуска при входе и ежедневной проверки в 09:00; недельный обзор остаётся отдельной оценкой семи предыдущих дней. Частота 300 секунд — параметр актуальности интерфейса, не рекомендация длительности работы. Сводка за вчера сохраняется в прежнем датированном файле и `latest.json`, текущие неполные сутки — только в `current-day.json`.

Повторная `prepare` не служит обновлением и ничего не перезаписывает. Для уже установленного принадлежащего каталогу runtime предусмотрено явное обновление из проверенных исходников:

```sh
python3 harness/scheduler.py upgrade --directory "$HOME/Library/Application Support/FocusDeckHarness"
python3 harness/scheduler.py status --directory "$HOME/Library/Application Support/FocusDeckHarness"
```

`upgrade` готовит новые файлы и хеши до остановки, проверяет владельца задания, сохраняет прежние runtime/config/plist в приватном `.upgrades`, останавливает только собственную загруженную задачу и атомарно меняет runtime. Выбранные источники, пользовательские параметры, токены и отчёты сохраняются. После обновления включённая ранее задача загружается снова; выключенная не активируется. При ошибке загрузки прежние файлы восстанавливаются и предпринимается одна попытка вернуть прежний процесс; окончательное состояние проверяется `status`. Обновление не скачивает код и не выполняется само. Резервные копии обновлений сохраняются для отката до отдельного удаления пользователем.

## Ошибочные будущие даты источника

Будущая дата устройства не превращается в «свежую» активность. Для каждого запуска фиксируется `evaluatedAtUTC`; если `occurredAt`, `startedAt` или `endedAt` позже этого момента, запись остаётся в исходном журнале для диагностики, но исключается из текущих часов, контекста и результатов. `clockDiagnostics` показывает количество и максимальную будущую дату. Неизвестное значение остаётся `null`, а корректные новые события после возврата часов продолжают учитываться.

`latestObservedAt` использует только записи без будущих времён. `latestReportedAt`/`latestFutureAt` сохраняют различие исходных дат, а `dailyCheck.state` и свежесть источника получают `clock_skew`. Отрицательный возраст не обрезается до нуля. Диагностический будущий event принимается приёмником и не блокирует последующие корректные загрузки.

Приёмник отдельно хранит время успешного приёма и первый серверный receipt по UUID в приватном `.receipt-metadata.json`, без имён запросов/текстов. Receipt доказывает связь, а не работу. Для будущих дат срок хранения дополнительно ограничен первым серверным receipt: дата 2030 года не удерживает содержимое до 2030 года. Для прежних записей применяется ограниченный момент миграции; метаданные не являются вторым источником продуктивности.

Недельный обзор не суммирует прежние отчёты без проверки часов либо отчёты, оценённые в будущем: они отмечаются как неизвестные/некорректные дни. Старый недельный формат пересоздаётся при следующем запуске. Это может уменьшить доступное покрытие, но не означает нулевую работу. Фиксированное `--as-of` существует для воспроизводимых синтетических проверок; обычный запуск использует текущие часы локального сборщика.

На личном пользователе телефона Android отказался назначить FocusDeck Guard владельцем устройства из-за существующих аккаунтов. Установка приложения сама по себе не включила управляемую блокировку. Аккаунты удалять и телефон сбрасывать не нужно. Повторять настройку через другой тип owner или менять системные setup-настройки не требуется.

**Main подтвердил завершённую проверку после отказа:** owner отсутствует; Guard показывает DORMANT, расписание отключено, `ownerBAL=false`, `exactAllowed=false`; единственным включённым администратором остаётся существующий StayFocused (`com.stayfocused`); резервное копирование включено; LockTask NONE. Для снятия ограничений Guard сейчас дополнительных действий не требуется. Инструкции ниже сохранены на случай будущей отдельно согласованной активации; повторять их после этого подтверждённого cleanup не нужно. Это результат проверки Main, не новое обращение агента Guard к телефону.

Без owner FocusDeck может ограничивать свой экран. Обычное закрепление Android снимается системным способом, указанным самим Android; это не управляемый режим Guard. Успех тестов на отдельном тестовом пользователе не означает полной защиты личного пользователя.

## Если Guard когда-либо был активирован и мешает выйти

Если доступен экран **FocusDeck Guard**, выберите действие восстановления и подтвердите его кодом блокировки телефона. Во время управляемой блокировки этот экран может быть недоступен — тогда используйте уже авторизованный компьютер. Сам FocusDeck, его дневник и хранилище для этого не нужны.

На подключённом компьютере выполните именно восстановление:

```sh
adb -s 62051JEA324712 shell am broadcast --user 0 \
  --receiver-foreground --include-stopped-packages \
  -n dev.stanislav.focusdeck.guard/.AdbRecoveryReceiver \
  -a dev.stanislav.focusdeck.guard.RECOVER
```

Ожидаемый ответ — `result=0` и `RESTORED`. Он означает, что Guard отменил свои alarm и проверил снятие своих политик. Отдельно проверьте, что телефон действительно вернулся к обычной навигации. Восстановление не меняет выбранный домашний экран и не удаляет запись owner. Оно не помечает ритуал выполненным и не меняет дневник.

**Для текущего отказа enrollment:** при подтверждённом отсутствии owner ответ RECOVER «Guard не является owner» ожидаем. Это не повод снова назначать owner. Наличие обычной admin-записи, если она осталась, проверяется и очищается отдельно.

## Если Guard не запускается или осталась его admin-запись

Main может снять только администратора **FocusDeck Guard** через Android, независимо от процесса приложения:

```sh
adb -s 62051JEA324712 shell dpm remove-active-admin --user 0 \
  dev.stanislav.focusdeck.guard/.GuardAdminReceiver
```

Этот запасной путь предусмотрен текущей сборкой с `testOnly=true`. Применять его после проверки, что запись Guard действительно есть; сообщение об отсутствующей записи само по себе не требует повторных действий. Компонент StayFocused и другие администраторы к этой команде не относятся.

После восстановления/удаления Main проверяет отсутствие owner Guard и его admin-записи, состояние LockTask `NONE` и резервное копирование. `NONE` описывает именно LockTask, а не все возможные ограничения других приложений. Не очищайте данные Guard и не удаляйте приложение до снятия его администрирования: это может лишить нормального журнала восстановления. Удалять аккаунты, включать root, сбрасывать телефон или менять Accessibility не нужно.

Эти команды здесь только описаны. Агент Guard не выполнял их на телефоне; итоговое состояние подтверждает Main.

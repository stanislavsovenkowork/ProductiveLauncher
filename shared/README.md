# Контракт событий FocusDeck v1

`event-v1.schema.json` — общий формат обмена; JSONL, одна запись на строку. Все времена UTC ISO 8601 с `Z` или `+00:00`. eventId — устойчивый UUID для устранения повторов; sessionId — один UUID на весь сеанс, null только вне сеанса. source = mac/android/movebreak; category = work/study/null (неизвестно, не угадывать). type описывает событие, evidence — основание измерения. Поля metrics допускают null; отсутствующее поле тоже означает «не измерялось», а не ноль.

startedAt/endedAt описывают фактический неперекрывающийся рабочий интервал, исключающий паузы. Таймер — proxy, не доказанное внимание; verified требует отдельного объяснения источника проверки. taskRef — существующий устойчивый ID задачи Obsidian, без копирования личного текста. outcome необязателен. deviceId — локальный псевдоним, не серийный номер. Сырые URL/тексты окон/клавиатура не собираются.

Отсутствие heartbeat не является событием uninstalled. Два устройства не суммируются дважды: объединение пересекающихся интервалов; противоречивые категории отмечаются как неоднозначные. Само событие completed не доказывает полезного результата. Реализация может хранить локальное состояние в удобной форме, экспортируя этот контракт; схема не требует писать в существующие Room/MoveBreak журналы.

## Общая семантика времени v1

`session-policy-v1.json`: 25 минут — номинальная цель рабочего отрезка, не обязательный cutoff учёта; одна пауза до 300 секунд; её выдача один раз продлевает заранее ограниченное окно защиты, общий потолок — 1800 секунд (30 минут). Работа в паузу не засчитывается. Ранний возврат не даёт нового продления, обычная остановка учёта не отменяет выбранное окно защиты. Возобновление работы требует явного действия; окончание послабления восстанавливает только реально доступные ограничения. При задержке возврата бюджет не растягивается бесконечно — показывается фактический остаток/окончание защиты.

Граничная проверка `integration/check_protection_boundary.py` сравнивает вывод настоящих Kotlin ProtectionWindow и Swift RootCommandCore/RootGuardCore/SessionState. На 25-й минуте после одного пятиминутного перерыва запрет ещё действует; на 30-й истекает. Это соответствие семантики, **не утверждение о живой синхронизации запуска двух устройств**. Полный live общий старт/рассылка/подтверждение политик ещё отдельный открытый критерий.

Учёт после номинальной цели может продолжаться, пока состояние явно running; интерфейс показывает, что плановое время прошло. Это не продлевает защиту. После её предела показывается «учёт идёт, ограничения закончились»; следующий защищённый отрезок начинается только явным действием. Мы не заставляем пользователя прерывать чтение каждые 25 минут ради нового таймера.
